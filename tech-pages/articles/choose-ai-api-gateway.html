What an AI API gateway is

A vendor API is that vendor’s own interface, with its own key and host. An AI API relay sits between your program and those vendors, forwards an OpenAI-compatible request, and converts it to the Claude API or Gemini protocol when needed. LingTrue is that kind of LLM gateway: one token and one host in front of GPT, Claude, or Gemini.

The gateway reduces the number of integrations. It does not decide which answer is better. Quality still depends on the model ID and the prompt. The gateway keeps fewer keys, records usage in one place, and lets an existing SDK change models without a rewrite.

Five checks before you pick a gateway

  1. Protocol. Confirm POST /v1/chat/completions, and POST /v1/messages if a tool speaks the Claude API. A chat website with neither HTTP API is not an OpenAI-compatible gateway.
  2. A Base URL you can document. LingTrue’s code host is https://www.lingtrue.com/v1. Desktop clients use https://www.lingtrue.com. Written rules prevent a broken path when you change clients.
  3. One key, many models. The same token should switch GPT, Claude, and Gemini with the model field.
  4. Prices visible before you call. Usage billing with no monthly fee describes the meter, not the rate. Each model’s input and output price is whatever the pricing page shows at that moment.
  5. A client you can actually configure. Cherry Studio: Cherry Studio setup. AionUI: AionUI setup. Your own code: the 3-minute quickstart and the API docs.

A decision sequence

  1. List the vendors you must call. If there is one vendor and the contract locks you to its official API, skip the gateway.
  2. Decide whether the client needs OpenAI compatibility or the native Claude API /v1/messages path. LingTrue uses one token for both. Split the Base URL as in the fact table.
  3. Keep two or three model IDs from the task table and write down their input and output prices from the pricing page.
  4. Send one real prompt in a small batch to each. Keep the model that follows the format, and keep a fallback.
  5. Put the Base URL and key in Cherry Studio, AionUI, or your SDK. Store the key in a server or the client’s key field, not in a public repository.

FAQ

How is an AI API gateway different from a vendor API?

A vendor API is that vendor’s own interface, with its own key and host. An AI API gateway sits between the client and several vendors and translates the request. LingTrue exposes the OpenAI-compatible Base URL https://www.lingtrue.com/v1, so most existing OpenAI SDK code changes the host and the key.

How do I tell that a gateway is OpenAI compatible?

It should offer POST /v1/chat/completions and GET /v1/models, with model and messages in the body. LingTrue’s API docs describe those endpoints. A chat website without those HTTP APIs is not an OpenAI-compatible gateway.

For Claude, should I use the OpenAI-compatible API or the native Claude API?

If you already use the OpenAI SDK, change model to a Claude model ID and set the Base URL to https://www.lingtrue.com/v1. If you need the official Anthropic SDK or /v1/messages, set base_url to https://www.lingtrue.com and let the SDK append the path. Both use the same LingTrue token.

Should I choose a model for quality or for price first?

Fix the task, compare input and output prices on the pricing page, then run the same prompt through two or three models at low volume. Simple bulk work starts with a small model. Code, long writing, and hard reasoning move up to Claude or a larger GPT. Unit prices are live on the pricing page. Do not budget from an old article.

What happens if the Base URL is wrong?

An extra /v1 becomes /v1/v1/chat/completions and usually returns 404. Putting /chat/completions in the Base URL also duplicates the path the client appends. Cherry Studio and AionUI use https://www.lingtrue.com. The OpenAI SDK uses https://www.lingtrue.com/v1.
