AI API 中转（大模型网关）把多家模型收成一个 OpenAI 兼容入口，用一个 Base URL 和一个 API Key 调用 GPT、Claude、Gemini。若你要同时用多家模型，优先选协议完整、按量计费可核对、并能在客户端里只改模型名的网关；模型档位按任务选，具体单价以 LingTrue 定价页 的实时数字为准，不要用文章或聊天记录里的旧价格做预算。

结论：统一接入 GPT、Claude、Gemini 时，代码侧 OpenAI 兼容 Base URL 使用 https://www.lingtrue.com/v1，Cherry Studio 与 AionUI 使用根地址 https://www.lingtrue.com。先定任务，再在定价页比较候选模型，最后用同一条提示词小流量试跑。

AI API 中转是什么

官方 API 是模型厂商自己的接口，每家有独立密钥和地址。AI API 中转站在你的程序和这些厂商之间，把 OpenAI 兼容请求转发到对应上游，并在需要时转换成 Claude API 或 Gemini 的协议。LingTrue 就是这样的大模型网关：对开发者暴露一套令牌和地址，后面可以是 GPT、Claude 或 Gemini。

它解决的是接入数量，不是替你决定哪条回答更好。质量仍取决于模型 ID 和提示词。网关负责少配几套密钥、把账单收成按量记录，并在你更换模型时不必重写 SDK。

选型时核对这 5 件事

  1. 协议。确认有 POST /v1/chat/completions，并且 Claude 工具能走 POST /v1/messages。只有聊天网页、没有这些 HTTP 接口的，不是 OpenAI 兼容网关。
  2. Base URL 是否稳定、可公开说明。LingTrue 的代码地址是 https://www.lingtrue.com/v1，桌面客户端填 https://www.lingtrue.com。地址规则写进文档，才不容易在换客户端时配错。
  3. 一把密钥覆盖的模型。同一令牌应能通过 model 切换 GPT、Claude、Gemini，而不是每家再发一把 Key。
  4. 价格能否在下单前看到。按量计费、无月费只是计费方式。每个模型的输入和输出单价以 定价页 当时显示为准。
  5. 你的客户端是否好配。Cherry Studio 见 Cherry Studio 配置，AionUI 见 AionUI 配置，自写代码见 3 分钟接入 和 接入文档。

常见问题

AI API 中转和官方 API 有什么区别？

官方 API 是模型厂商自己的接口，每家有独立的密钥和地址。AI API 中转（大模型网关）站在客户端和多家厂商之间，把请求转成对应协议。LingTrue 对开发者暴露 OpenAI 兼容的 Base URL https://www.lingtrue.com/v1，因此多数现有 OpenAI SDK 代码只改地址和密钥。

怎样确认一个网关是 OpenAI 兼容的？

看它是否提供 POST /v1/chat/completions 和 GET /v1/models，并且请求体使用 model 与 messages。LingTrue 的 接入文档 说明了这些端点。只提供聊天网页、没有上述 HTTP 接口的，不能当作 OpenAI 兼容网关。

选 Claude 时应该走 OpenAI 兼容还是 Claude API 原生协议？

已经在用 OpenAI SDK 时，把 model 换成 Claude 的模型 ID 即可，Base URL 用 https://www.lingtrue.com/v1。需要 Anthropic 官方 SDK 或 /v1/messages 的工具时，base_url 用 https://www.lingtrue.com，由 SDK 自己拼接路径。两种方式使用同一把 LingTrue 令牌。

模型选型应该先看效果还是价格？

先固定任务，再用定价页比较候选模型的输入和输出单价，然后用同一条提示词小流量试两到三个模型。批量、格式简单的任务优先小模型；代码、长文和强推理再上 Claude 或更大的 GPT。具体单价以 定价页 实时为准，不要用文章里的旧价格做预算。

Base URL 填错会有什么表现？

多写一层 /v1 时，请求会变成 /v1/v1/chat/completions，通常返回 404。把 /chat/completions 写进 Base URL，也会和客户端自动拼接的路径重复。Cherry Studio 与 AionUI 填 https://www.lingtrue.com；OpenAI SDK 填 https://www.lingtrue.com/v1。
